# Releases

rbinkd uses Semantic Versioning and publishes GitHub Releases from tags.
The release workflow builds every supported artifact, writes checksums,
and creates the Release only after all builds pass.

## Versioning

- The version is `[workspace.package].version` in `Cargo.toml`.
- Tags use `vMAJOR.MINOR.PATCH`, for example `v0.1.0`.
- The workflow refuses to publish unless the tag equals `v<version>`.
- While the major version is zero, a minor release may introduce breaking
  changes and a patch release carries fixes.
- `Cargo.lock` is committed and every release build uses `--locked`.
- Release notes are generated by GitHub from the commits since the previous
  Release. This repository does not keep a separate changelog.
- The optional `rbinkd-perl` and `rbinkd-win-ffi` crates are not published
  and keep their own versions.

## Release process

1. Update `[workspace.package].version` in `Cargo.toml`.
2. Run `cargo check --workspace` to refresh `Cargo.lock`.
3. Run the local checks from the [development guide](development.md).
4. Commit the version change.
5. Create an annotated tag:

   ```sh
   git tag -a v0.1.0 -m "rbinkd v0.1.0"
   git push origin master
   git push origin v0.1.0
   ```

The tag starts the `Release` workflow. It does not run the regular CI
matrix; the release check job runs the workspace tests, clippy, and the
format check first.

## Targets

The release publishes the default build. The optional `perl` and
`windows-original` variants are not part of a release.

Linux glibc, built with Zig and `cargo-zigbuild` for glibc 2.17. The
workflow pins Zig 0.17.1 and cargo-zigbuild 0.24.1; Zig 0.16 does not link
the MIPS targets:

- `x86_64-unknown-linux-gnu`
- `aarch64-unknown-linux-gnu`

Linux musl, statically linked:

- `armv7-unknown-linux-musleabihf`
- `aarch64-unknown-linux-musl`
- `armv5te-unknown-linux-musleabi`
- `i686-unknown-linux-musl`
- `x86_64-unknown-linux-musl`
- `mips-unknown-linux-musl`
- `mipsel-unknown-linux-musl`

The MIPS targets are Tier 3 Rust targets without prebuilt `std`. The
workflow installs nightly with `rust-src` and uses
`-Z build-std=std,panic_abort` for those two targets. Every musl binary is
checked with `readelf -d` and must have no `NEEDED` entries.

macOS and Windows build on native runners:

- `x86_64-apple-darwin`
- `aarch64-apple-darwin`
- `x86_64-pc-windows-msvc`

## Assets

Each Unix archive is named `rbinkd-<tag>-<target>.tar.gz`; the Windows
archive is a `.zip`. The archive holds a directory with the binary and:

- `README.md`
- `COPYING`
- `rbinkd.8`
- `binkd.conf`
- `binkd.cfg`

The Release also holds `SHA256SUMS`. GitHub adds the source archives.

The publish job first creates a draft Release, uploads the archives, and
then publishes the draft. A failed build or upload therefore does not
produce a public partial Release.

## Publishing scope

The workflow publishes GitHub Release assets only. It does not publish
crates to crates.io. Add that step when the library API and crate metadata
are ready, with a separate registry token and publish order.
